Weir にアカウント、アクセス解析、テレメトリはありません。動かすエージェントは、これまでどおりそれぞれのサービスと通信し、その規約に従います。

レビューのコメントを挿入すると、コメントと該当するコードの抜粋がエージェントの入力欄に貼り付けられます。それを送信すると、内容はエージェントが使っているモデルに送られます。非公開のコードにコメントを送る前に、ペインのヘッダーでモデルを確かめてください。

## Weir が送るもの

Weir がネットワークを使うのは、次の場合だけです。

| 用途 | 内容 |
|---|---|
| アップデートの確認 | 1 日に 1 回、GitHub から更新情報を取得します。リリースをダウンロードするのは、インストールを選んだときだけです |
| 新規ワークツリー | リモートのブランチや PR から始めるときに、お使いの Git の認証情報で `git fetch` を実行します。PR から始めるときは、インストール済みの `gh` か `glab` で PR の一覧を取得するか、番号で PR を調べます |
| PR の状態 | インストール済みの `gh` か `glab` を、その認証情報で、プロジェクトのブランチすべてについてまとめて 1 回実行します。Weir が前面に来たときとターンが終わったときは、多くても 1 分に 1 回です。そのほかは、チェックの実行中は 45 秒ごと、開いている PR があれば 90 秒ごと、PR のないブランチは 5 分ごとです。マージ済みやクローズ済みの PR は、多くても 1 時間に 1 回しか調べません。サービスのレート制限に達したときは、制限が解除されるまで問い合わせを止めます。見慣れないホストがどのサービスかを調べるために、ホストごとに 1 回 `gh auth token` か `glab auth status` も実行します |
| PR を作成 | 選んだときに、インストール済みの `gh` を実行します |
| プラン使用量 | インストール済みの `codex` を起動して、プランの使用量を尋ねます |

毎日の確認を止めるには、**設定 → 一般 → ソフトウェアアップデート** の **アップデートを自動的に確認する** をオフにします。手動で確認するときは、**アップデートを確認…** を使います。

## Weir が書き込むもの

- **エージェントのフック。** `~/.claude/` と `~/.codex/` には何も追加せず、中身も変更しません。0.1.11 以前のバージョン（当時の名前は Limpid）が `~/.codex/config.toml` に追加したフックの信頼設定は、現在は使われていないため、削除してかまいません。Weir のペインでは、小さな `claude` と `codex` のラッパーを `PATH` の先頭に置き、起動のたびにフックを渡します。Weir の外で起動したエージェントには影響しません。`claude` のラッパーは、ご自身で指定した `--settings` があればそれと統合し、フックのコマンドへのリンクを一時フォルダーの `weir-claude-shim-*` に置きます。Claude Code や Antigravity でご自身のステータスラインを使っている場合は、その位置に Weir の中継役が入ります。中継役は、エージェントから渡されるプランの使用量を受け取ったあと、同じ入力でご自身のステータスラインを実行します。`agy` をご自身の `--settings` 付きで起動した場合は、その設定をそのまま使い、使用量は表示されません。
- **Antigravity のプラグイン。** `agy` はコマンドラインでフックを受け取らないので、Weir のペインで最初に `agy` を起動したときに、`~/.gemini/config/plugins/weir` にプラグインを置きます。Weir のものであることは、中の `.weir-managed` ファイルで見分けます。このファイルがない同名のフォルダーには触れません。Weir のペインの外では、プラグインは何もしません。止めるには `agy plugin disable weir` を実行します。フォルダーを削除した場合は、次に Weir のペインで `agy` を起動したときに、また置かれます。
- **OpenCode のプラグイン。** Weir のペインで最初に `opencode` を起動したときに、`~/.config/opencode/plugins/weir` にプラグインを置きます。Weir のものであることは、中の `.weir-managed` ファイルで見分けます。このファイルがない同名のフォルダーには触れません。Weir のペインの外では、プラグインは何もしません。フォルダーを削除した場合は、次に Weir のペインで `opencode` を起動したときに、また置かれます。OpenCode の設定やサインイン情報を読んだり変えたりすることはありません。Weir は自身の環境変数を除いて OpenCode を起動するため、それらの変数はエージェントが実行するコマンドには渡りません。代わりに小さなファイルでプラグインに渡し、プラグインは読み込んだあとにそのファイルを削除します。
- **Kiro のフックファイル。** Kiro はコマンドラインでフックを受け取らないので、Weir のペインで最初に `kiro-cli` を起動したときに、`~/.kiro/hooks/weir.json` にフックファイルを置き、書いた内容のチェックサムをその隣に残します。Weir が書いていない同名のファイルには触れません。Weir のファイルも、ご自身で編集したあとは書き換えません。Weir のペインの外では、フックは何もしません。ファイルを削除した場合は、次に Weir のペインで `kiro-cli` を起動したときに、また置かれます。ターンを把握するために、Weir は Kiro が `~/.kiro/sessions/` に残すセッションログを読みます。そこには何も書き込みません。
- **承認サービス。** リリース版は、ユーザーごとのバックグラウンドサービスを登録します。**システム設定 → 一般 → ログイン項目と機能拡張** に表示されます。
- **ターンのスナップショット。** 各リポジトリの Git ディレクトリに、`refs/weir/` の参照と `weir/` のファイルとして保存します。

## データの場所

| 内容 | 場所 |
|---|---|
| セッション、設定、通知履歴、スクロールバック、レビューの下書き、ターンの記録 | `~/Library/Application Support/Weir/` |
| 環境設定 | `~/Library/Preferences/com.nekoder.Weir.plist` |
| ターンのスナップショット | 各リポジトリの Git ディレクトリ |

スナップショットは、14 日経つか 1 つの会話で 200 件を超えると削除されます。リポジトリのスナップショットが 500 MB を超えたとき、ターンが全体で 8,000 件を超えたときも同じです。開いているセッションの未確認のターンは、最大 90 日残ります。**設定 → 詳細設定 → ターンの記録** で変更できるのは、日数と会話ごとの件数です。ほかの上限は固定です。

すべて削除するには、[アンインストール](/ja/docs/install/#アンインストールする)を見てください。
