## ターンが要対応から消えない

ファイルを変更したターンは、確認済みにするまで残ります。<kbd>⌘⏎</kbd> で **確認済みにする** を実行してください。[変更をレビューする](/ja/docs/review/#ターンを確認済みにする)も見てください。

## 承認がカードに出ない

カードは自動では開きません。次の場所にある **回答…** を選んで開きます。

- エージェントのペインの下のバー（<kbd>⌘⏎</kbd> でも開きます）
- **要対応** の一覧
- **すべてのプロジェクト**
- サイドバーのワークツリーの行（カーソルを合わせると表示されます）

**ターミナルで回答** でプロンプトに渡した依頼には、エージェントのプロンプトで答えてください。

すべての承認がプロンプトに表示されるときは、**システム設定 → 一般 → ログイン項目と機能拡張** で Weir のサービスがオンか確かめてください。ディスクイメージから開いた Weir や、macOS が一時的にコピーして開いた Weir はサービスを登録しないので、「アプリケーション」フォルダーに移動して、そこから開き直してください。

## 実行中や承認待ちの表示が消えない

tmux の中で起きることがあります。Claude Code のターンを <kbd>Esc</kbd> や <kbd>⌃C</kbd> で止めたり、ダイアログで拒否したりしても、そのペインで次のプロンプトを送るまで Weir に伝わりません。次のプロンプトを送れば消えます。

`CLAUDE_CODE_DISABLE_TERMINAL_TITLE` を設定している場合は、tmux の外でも同じことが起きます。

## Claude Code のプラン使用量が出ない

Claude Code は使用量をステータスラインにしか渡さないので、ご自身のステータスラインが必要です。Claude Code で `/statusline` を実行して設定してください。Weir のペインで次に返答があったときに表示されます。

## Codex のプラン使用量が出ない

ChatGPT で Codex にサインインしていると表示されます。Weir は `~/.codex` のアカウントを読むので、シェルで `CODEX_HOME` を設定していても、読むアカウントは変わりません。

## Antigravity のプラン使用量が出ない

Antigravity は使用量をステータスラインにしか渡さないので、ご自身のステータスラインが必要です。`agy` で `/statusline` を実行して設定してください。Weir のペインで次に返答があったときに表示されます。`--settings` をご自身で渡して起動した場合は表示されません。

## Antigravity がずっと作業中のままになる

ご自身で起動した tmux の中で起きることがあります。そこでは `agy` が状態を知らせないので、生成を止めたり質問を取り消したりしても、次のプロンプトを送るまで作業中のままです。許可の確認も、承認待ちとして表示されません。Weir が `agy` を tmux の中で動かすことはないので、ペインで直接起動すれば起きません。

## Antigravity の状態が Weir に出ない

Weir のペインで初めて `agy` を起動したときに、Weir が `~/.gemini/config/plugins/weir` にプラグインを置きます。同じ名前のフォルダーが `.weir-managed` ファイルなしですでにあると、Weir は触れません。そのフォルダーを別の場所に移してください。`agy plugin disable weir` を実行していた場合は、`agy` でプラグインを有効に戻してください。

## OpenCode の状態が Weir に出ない

Weir のペインで初めて `opencode` を起動したときに、Weir が `~/.config/opencode/plugins/weir` にプラグインを置きます。`OPENCODE_CONFIG_DIR` を設定しているときは、そのフォルダーの `plugins/weir` に置きます。同じ名前のフォルダーが `.weir-managed` ファイルなしですでにあれば触れないので、別の場所に移してください。`--server` を付けた起動と、`opencode run` などのサブコマンドは見守りません。Weir が対応していない新しい OpenCode では、プラグインが使う機能が変わっていて、ペインが通常の OpenCode として動くことがあります。

## OpenCode のターンに変更が出ない

ターンの開始点は、<kbd>Return</kbd> を押したときに保存します。`--prompt` で起動したときは、OpenCode が立ち上がる前に保存します。メニューから選んだスラッシュコマンド、割り当てを変えた送信キーで送ったプロンプト、エージェントが自分で続けるターンには開始点がないので、変更の集計も **コードを復元** も表示されません。大きなリポジトリなどで保存に 10 秒以上かかったときも開始点はなく、入力はそのまま送ります。

## Kiro の状態が Weir に出ない

Weir が見守るのは、フックを読み込む Kiro の v3 エンジンだけです。Weir が開く Kiro のタブは `kiro-cli --v3` で起動します。ご自身で入力した `kiro-cli` は、Kiro 3.0 以降なら v3 で動きます。ただし、v2 を使い続ける設定にしたときや、`--no-interactive` を付けて起動したときは v2 で動きます。`--v3` を付けるか、Kiro の設定で v3 を選んでください。Weir のペインで初めて `kiro-cli` を起動したときに、Weir が `~/.kiro/hooks/weir.json` にフックファイルを置きます。同じ名前のファイルがもともとあったときや、Weir のファイルを編集したあとは触れないので、別の場所に移してください。信頼していないフォルダーでは、Kiro はフックを実行しません。`KIRO_HOME` を別の場所に向けているときも、`~/.kiro` のフックは読まれません。クラウドセッション（`--cloud`）は Kiro のサンドボックスで動くので、Weir は見守りません。

## Kiro がずっと作業中のままになる

ご自身で起動した tmux の中で起きることがあります。そこでは `kiro-cli` が状態を知らせないので、<kbd>Esc</kbd> でターンを止めても、次のプロンプトを送るまで作業中のままです。許可の確認も、承認待ちとして表示されません。Weir が `kiro-cli` を tmux の中で動かすことはないので、ペインで直接起動すれば起きません。

## 行に PR の状態が出ない

`gh` か `glab` をインストールして、プロジェクトのリモートにサインインしてください。**PR を作成** には `gh` が必要なので、GitLab のマージリクエストは Weir からは作成できません。

状態が変わらなくなったときは、サービスのレート制限に達したのかもしれません。その間、Weir は最後の状態を表示したまま、制限が解除されてから取得し直します。

## 新規ワークツリーに未コミットの変更を持ち込めない

変更を持ち込むには Git 2.41 以降が必要です。ワークツリーでマージやリベースの途中のとき、コンフリクトがあるとき、スパースチェックアウトを使っているときも、Weir は何も作成せずに止まります。先にそれを完了するか中止するか、変更を持ち込まずに作成してください。

Git が無視するファイルは持ち込まれません。`.env` などをコピーするには、**プロジェクト設定** で選んでください。

## ターンの最初や最後でプロンプトが止まる

Weir はターンの最初と最後にスナップショットを取ります。スナップショットの取得が滞ると、プロンプトが最大 10 分止まることがあります。何度も起きるときは報告してください。

## 古いターンが消えた

古いターンは自動で削除されます。長く残すには、**設定 → 詳細設定 → ターンの記録** で日数と会話ごとの件数を増やしてください。上限の一覧は[プライバシーとデータ](/ja/docs/privacy/#データの場所)にあります。

## それでも解決しないとき

まだ動かないことの一覧は、[Known limitations](https://github.com/nek0der/weir/blob/main/docs/known-limitations.md)（英語）にあります。

[Discussions](https://github.com/nek0der/weir/discussions) で質問するか、[Issue](https://github.com/nek0der/weir/issues) を作成してください。その際は、Weir と macOS のバージョン、使っているエージェント、期待した動作と実際の動作を書き添えてください。開発は 1 人で行っているので、返信に時間がかかることがあります。

セキュリティの問題は Issue にせず、[セキュリティポリシー](https://github.com/nek0der/weir/blob/main/SECURITY.md)に従って報告してください。
